# GreenAI — генеративный дизайн городского озеленения

Пайплайн `DXF → карта ограничений по НПА → план посадок → DXF + обоснование`.

Результат пишется в отдельные слои `GREEN_AI_TREES`, `GREEN_AI_SHRUBS`,
`GREEN_AI_ZONES`, `GREEN_AI_NOTES`. Исходные слои не изменяются.

* Сопроводительная документация: [docs/GreenAI_документация.pdf](docs/GreenAI_документация.pdf)
  (также `.docx`; исходник — [docs/DOCUMENTATION.md](docs/DOCUMENTATION.md)).
* Пример входа и выхода: [examples/](examples/).
* Запуск в Docker: `docker compose build && docker compose up` → http://localhost:8000.

## Папки

| Папка | Назначение |
|---|---|
| `input/` | сюда кладутся файлы для анализа: DXF, DWG, векторный PDF |
| `output/` | сюда складываются результаты, по папке на каждый расчёт |
| `config/` | справочник нормативов и каталог пород |

## Веб-интерфейс

```bash
python src/webapp.py
```

Откроется http://127.0.0.1:8000 — загрузка файла, выбор сценария и схемы
размещения, живой журнал расчёта, ссылки на результаты. Под Windows есть
`run_web.bat`, под Linux — `run_web.sh`.

Документация API по OpenAPI доступна на http://127.0.0.1:8000/docs —
расчёт можно запускать и программно, без интерфейса.

Страницы:
- **Просмотр чертежа** — схема, раскрашенная по классам слоёв, до расчёта;
  открывается сразу после загрузки файла. Нераспознанное — красным.
  Разобранные чертежи кешируются в `cache/`, повторно открываются за секунды.
- **Слои чертежа** — ручное назначение классов; доля нераспознанного
  считается по длине линий, как в расчёте.
- **Модель посадки → Разметить имена без класса** — частые имена слоёв со
  всех прогнанных проектов, которых не знают правила. Разметка сразу
  работает в расчёте и пополняет выборку ручными примерами.
- **Сводка расчёта → Проверка результата** — откуда взят участок, где стоят
  деревья, доля нераспознанного, сети, правило 10-20-30.

## Быстрый старт

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # Linux / macOS

pip install -r requirements.txt

python src/make_sample.py                          # тестовый чертёж
python src/main.py --input data/sample.dxf --outdir out
```

## Что получается на выходе

| Файл | Что внутри |
|---|---|
| `*_GREEN_AI.dxf` | исходный чертёж + слои результата |
| `*_explain.json` | машиночитаемое обоснование каждой посадки |
| `*_explain.csv` | то же таблицей, открывается в Excel |
| `*_report.md` | отчёт с таблицей ограничений и ссылками на НПА |
| `*_schedule.csv` | ассортиментная ведомость: порода → количество |

## Параметры

```
--tree tilia_cordata        порода дерева из config/species.yaml
--shrub cotoneaster_lucidus порода кустарника

```

Нормативы правятся в `config/norms.yaml` без изменения кода.

## Docker

Запуск прототипа. Нужен только Docker. Образ собирается на Debian и
включает ODA File Converter для Linux, поэтому DWG из набора
«Пилотный проект 20 улиц» читается прямо в контейнере.

```bash
git clone https://github.com/Kaban425/greenai && cd greenai
docker compose build                      # или: docker build -t greenai:latest .
docker compose up                         # сайт http://localhost:8000, Swagger /docs
```

Расчёт из командной строки на учебном чертеже (результат — в `./output/run1`):

```bash
docker compose run --rm greenai python src/main.py \
    --input data/sample.dxf --outdir output/run1 --plan-only
docker compose run --rm greenai python src/verify_output.py \
    data/sample.dxf output/run1           # проверка: исходные слои целы, у посадок есть нормы
```

Готовый пример входного и выходного DXF с объяснениями лежит в
[examples/](examples/): `sample_input/sample.dxf` →
`sample_output/sample_GREEN_AI.dxf`, `_explain.json`, `_explain.csv`, `_report.md`.

Свой чертёж кладётся в `./input`. Если это комплект с внешними ссылками
(генплан eTransmit и папки ссылок рядом), папку монтируют целиком:

```bash
docker run --rm -v "/путь/к/комплекту:/app/input/obj" -v "$PWD/output:/app/output" \
    greenai:latest python src/main.py --input "input/obj/Генплан.dwg" --outdir output/obj
```

## Импорт подосновы из PDF

Если геоподоснова подключена к DWG внешними ссылками, а сами файлы xref
отсутствуют, сети можно извлечь из векторного PDF: чертежи, напечатанные
драйвером AutoCAD "DWG To PDF", сохраняют слои CAD вместе с геометрией.

```bash
python src/pdf_import.py "data/05_Генплан.pdf" --pages 1 --dry-run
python src/pdf_import.py "data/05_Генплан.pdf" --pages 1 -o data/podosnova.dxf
python src/main.py --input data/podosnova.dxf --outdir out_real
```

Масштаб по умолчанию 0,17639 м на единицу PDF (печать 1:500). Проверяется
по строке "Габариты извлечённой геометрии" в выводе --dry-run.

Страницы обрабатываются по одной: каждый лист чертежа имеет собственную
систему координат листа, и объединение страниц наложит их друг на друга.

PDF можно подать и прямо в `main.py --input …pdf`: геометрия извлекается
в `cache/pdf`, а без `--pages` берётся лист с наибольшим числом
распознанных линий.

## DWG на входе (автоматически)

Файл с расширением .dwg конвертируется на лету через ODA File Converter.
Конвертер ищется в стандартных папках установки; если он лежит в другом
месте, путь задаётся переменной окружения:

```powershell
$env:ODAFC_PATH = "C:\Program Files\ODA\ODAFileConverter 26.2\ODAFileConverter.exe"
python src/main.py --input "data/Генплан.dwg" --outdir out
```

## DWG вручную

Библиотека читает только DXF. DWG конвертируется бесплатной утилитой
ODA File Converter (есть сборка под Linux) в DXF R2010, после чего
подаётся в пайплайн.

## Как устроен расчёт

Территория разбивается на растровую сетку (по умолчанию 25 см). Для каждого
класса объектов строится карта расстояний (distance transform), после чего
проверка норматива в точке — сравнение двух чисел. Время расчёта зависит от
площади участка, а не от числа линий в чертеже: реальная подоснова с сотней
тысяч штрихов пунктира обрабатывается за секунды.

Итог проверяется трижды: отступы по картам расстояний, попадание в
допустимую зону и — независимо от растра — точные расстояния от каждой
посадки до исходных полилиний сетей и знаков чертежа. Посадка, не
прошедшая вторую или третью проверку, в результат не попадает: на
больших чертежах ячейка грубеет, и растр мог бы пропустить нарушение.

Внешние ссылки чертежа (топосъёмка, сети ДЖКХ, борт, заливки) подгружаются
сами: файлы ищутся по путям из чертежа и по имени в его папке и на уровень
выше, геометрия переносится по точке вставки. Если чертёж скопирован без
папок комплекта, укажите исходную папку: `--xref-dir <папка>`. Файлы той же
улицы, не подключённые ссылкой, добавляются ключом `--with <файл>`.

Деревья у проезжей части сажаются аллеей: ряд на постоянном отступе от
борта (ближайший допустимый плюс 0,5 м), повторяющий изгибы улицы. Ряды
существующих деревьев продолжаются с их же шагом. Прежняя схема — ключи
`--no-alley` и `--no-row-extend`.

Прогон по всем улицам — `python src/batch_streets.py <папка пилота>`,
сводка на странице «Улицы».

Модель выбора места (`python src/train_placement.py <папка проектов>`)
учится на посадочных планах многих улиц сразу и проверяется «без одной
улицы». Признаки — расстояния до объектов с порогами 1,5 / 3 / 6 м,
ширина полосы и близость к её оси.

Ключи расчёта:

```
--cell 0.25              размер ячейки сетки, м (меньше — точнее и медленнее)
--clip x0,y0,x1,y1       считать только фрагмент чертежа
--trees-per-ha 150       плотность посадки
--mode street|grove|mixed  стратегия размещения
--max-shrubs 3000        потолок числа кустарников
```

## Локальная модель (Ollama)

Модель дораспознаёт слои, которые не поняли правила. Веса не дообучаются:
знания о московских соглашениях об именах зашиты в Modelfile, а к каждому
запросу подкладываются похожие размеченные слои из `config/layer_dataset.jsonl`.
Выборка пополняется каждым расчётом, поэтому модель «учится» на новых чертежах.

```bash
python src/train_layers.py              # сверить выборку с правилами, обучить модель имён
python src/ollama_build.py --create     # собрать greenai-layers из config/Modelfile
python src/eval_llm.py --model greenai-layers   # точность на выборке
```

Если в Ollama есть `bge-m3` (`ollama pull bge-m3`), модель имён получает
второе мнение: неуверенный ответ принимается, когда векторная модель
согласна. Векторы кешируются в `config/layer_embeddings.npz`.

Газон, границу работ и «не учитывать» модель назначить не может — только
препятствие или оформление. Такие предложения отклоняются и видны в сводке.

### Пополнение выборки и дообучение (LoRA)

```bash
# имена слоёв из папки с проектами (DWG конвертируются ODA во временную папку)
python src/harvest_layers.py "<папка «Пилотный проект 20 улиц»>" --tmp <временная папка>

# дообучение в отдельном окружении с PyTorch (CUDA) и Unsloth.
# Всё одной командой, журнал в logs\lora.log (около часа на RTX 5060 Ti):
run_lora.bat
# или по шагам:
.venv-train\Scripts\python src\train_lora.py          # адаптер в models/greenai-lora
.venv-train\Scripts\python src\lora_to_ollama.py      # модель greenai-layers-lora
python src/eval_llm.py --model greenai-layers-lora --holdout
```

`train_lora.py` откладывает 10% имён (`config/lora_split.json`); `--holdout`
проверяет модели только на них — на том, чего дообученная модель не видела.

Ollama 0.3x не подключает адаптеры LoRA, поэтому `lora_to_ollama.py`
вливает адаптер в базовую модель, переводит её в GGUF `q8_0` конвертером
llama.cpp (`git clone --depth 1 https://github.com/ggml-org/llama.cpp
tools/llama.cpp`) и создаёт модель Ollama. На 8 ГБ видеопамяти дообучается
Qwen3-4B; 8B не помещается, если рабочий стол уже занял полтора гигабайта.
Unsloth при установке ставит torch без CUDA — после `pip install unsloth`
переустановите сборку `cu130` с download.pytorch.org.
Имена, которые не распознали правила, копятся в `config/harvest_unknown.txt`:
их ручная разметка учит модель тому, чего не знают правила.

## Границы MVP

- Работа ведётся в системе координат исходного чертежа, пересчёт в WGS84 не выполняется.
- Учитываются только те слои, которые распознал классификатор; нераспознанные
  перечисляются в отчёте и в консоли.
- Отступы по СП 42.13330.2016, таблица 9.1. Пункты московских ППМ 743 и 623
  вносятся в `config/norms.yaml` по мере уточнения.
